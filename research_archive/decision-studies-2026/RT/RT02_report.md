# RT-02 —— 一次受控的完成反馈实验

> # ⚠️ 本轮的 KM 回退实现有误，结论已由 RT02R_report.md 取代
>
> 具体问题：KM 的两种回退规则被合并成回退到**历史全局中位数**，而协议要求分别是
> 「组稀疏 → 该方法的全局估计（全局 KM）」与「中位数不可识别 → 该作业的 HISTORY 预测」。
> 此外时间跨度未沿用旧冻结值，隐藏标签扰动检查只做了第一个窗口且未重算预测。
> RT-02R 已修正这四处；保留本文件作记录。


## 结论

**门槛未通过。而且失败的原因不是方法优劣，而是设计的前提不成立：**
**在只用品类 A 的队列里，删失几乎不存在（0.7–0.9%）。**

四项预检全部通过。三个窗口的相对变化**没有一个为正**，等权平均 **−17.86%**，
预先固定的门槛（三窗口均为正且平均 ≥1%）**未达到**。

按预先固定的判读表，本轮落在**第 4 类（差异小或方向不一致）**：
记录为这个条件化队列上的**弱证据**；不写成整个方向无效，更不写成 oracle 上界。

## 1. 冻结的设置

| 项 | 值 |
|---|---|
| 记录 | 仅品类 A：全部任务有结束时间、存档状态 Terminated、时间有限、时长为正 |
| 标签 | `p_j = max_t e_jt − min_t s_jt` |
| 回放起点 | `min_t s_jt` |
| 研究对象 | **执行跨度的完成反馈**，不称为累计服务量 |
| 入选记录 | **732,355** |
| 时间跨度 | `542,323` .. `6,451,192`（68.4 天）|
| 更新点 | 跨度的 **40% / 60% / 80%**，不重选 |
| 近期训练队列 | 自 T 起**前 7 天**内开始的作业 |
| 测试队列 | 自 T 起**后 2 天**内开始的作业 |
| 近期队列可见通道 | `z_j = min(p_j, T−s_j)`，`δ_j = 1[e_j ≤ T]` |
| 目标 | 作业时长中位数 |
| 指标 | 平均绝对对数误差 `mean |log(1+p̂) − log(1+p)|` |

**条件化披露。** 只选品类 A 使用了存档后的信息（我们知道这些作业最终成功）。
因此这是**成功作业队列的条件化回放**，不是生产复现：部署时并不知道哪些在跑作业会成功。

## 2. 四项预检（全部通过）

| 预检 | 要求 | 结果 |
|---|---|---|
| 1 | 三个近期方法入选作业 ID 完全一致，只有标签权限不同 | **通过**：三个窗口的近期队列分别 72,687 / 81,029 / 95,694 个作业，**0 个重复 ID**，RECENT/KM/FULL-LABEL 由同一集合构造 |
| 2 | FULL-LABEL 覆盖率 100%，不允许静默丢记录 | **通过**：三个窗口均 **100.0000%** |
| 3 | 改动被遮蔽的最终时长（保持可见开始时间、删失状态、年龄不变）后，RECENT/KM 的输入不变 | **通过**：把隐藏侧的最终时长乘 1000 后，可见通道 `(z, δ)` 对整个近期队列**逐项不变** |
| 4 | 手算样本验证 KM：无删失、有并列与删失、曲线未达中位数 | **通过**（4 个用例 + 1 个置换不变性） |

### 2.1 KM 手算校验明细

| 用例 | 期望 | 实测 |
|---|---|---|
| 无删失，时刻 1..5 | 中位 3 | **3** |
| 并列 + 删失：2 事件@1（5 在险），1 事件@2（3 在险） | S: 0.6 → 0.4，中位 2 | **2** |
| 全部删失 | 未达 0.5 | **None** |
| 6 条中 1 个事件 | 未达 0.5 | **None** |
| 置换 (时刻, 事件) 对 | 结果不变 | **仅 1 个取值** |

并列时刻按「同一时刻的人一起处理」实现，因此风险集在同一时刻内相同，**并列顺序不可能影响结果**。
本轮没有自行实现分位数检验。

## 4. 为什么门槛没过：设计前提不成立

本轮预先固定的判读是这样写的：若传统删失估计已经足够，就不再开发复杂学习器。
实际发生的是更前置的一件事：**这个设计里几乎没有删失可纠正。**

| 事实 | 数值 |
|---|---|
| 近期队列的删失比例 | **0.7% – 0.9%** |
| FULL-LABEL 相对 RECENT 的改善 | 三个窗口分别 +0.00202 / +0.00210 / +0.00246（近乎为零） |

**含义：** 只用品类 A 之后，RECENT / KM / FULL-LABEL 拿到的基本是**同一份数据**。
三者的预测几乎相同，所以这个实验**结构上无法**回答「删失估计是否有用」。

这与质检轮（RT-01R）的标签资格结论完全一致：
**真正缺标签的那 23% 记录不在品类 A 里**，而把它们纳入又需要先把「在跑 / 失败 / 没记上」
区分开——那正是当前数据做不到的事。

### 4.1 另一个必须报告的事实

HISTORY 在两个窗口上**明显优于** RECENT 与 KM（1.37 vs 1.69、1.19 vs 1.50）。
按你预先固定的判读，这**不属于**第 3 类（「只有相对 RECENT 改善但不能超过 HISTORY」），
而是相反方向：长期历史更强。这条也要如实记录。

## 5. 判读

| 预先固定的档位 | 是否命中 |
|---|---|
| KM 相对 HISTORY 和 RECENT 都稳定改善 → 进入固定调度器验证 | **否** |
| FULL-LABEL 改善而 KM 没改善 → 提示估计方法未用好信息 | **否**：FULL-LABEL 本身几乎没改善 |
| 只有相对 RECENT 改善，不能超过 HISTORY → 不扩展 | **否**：方向相反，HISTORY 更强 |
| 各方法差异很小或方向不一致 → 弱证据，不写成方向无效 | **本轮实际落在这里**（且原因已定位） |

**因此：不进入调度器验证，也不开发复杂学习器。但这不是对方向的否定。**

本轮的可用产出是**一个结论清晰的负结果加一个已定位的原因**：
条件化成成功队列会把删失抹掉，所以这个设计测不到删失纠正的价值。

## 6. 限制

1. **条件化回放。** 只选品类 A 用了存档信息，不能宣称部署时知道哪些作业会成功。
2. **删失比例过低（<1%），因此本轮的比较没有检验力**，不能据此判断 KM 是否有用。
3. **回退主导。** KM 与 RECENT 有 87–91% 的测试作业走了回退路径，
   所以成绩主要反映回退规则，而非各自的估计。
4. **分组稀疏。** 217,982 个 group 中只有 5,955 个（覆盖 53.3% 作业）有 ≥30 条记录，
   而近期 7 天队列更小，导致回退率极高。
5. **只测执行跨度。** 未测排队延迟与响应时间（数据不含可观测的等待时间，见 RT-01R §5）。
6. **不接调度器。** 未测任何调度收益；也未测排序变化。
7. **未训练神经网络**，只用了分组经验中位数与 Kaplan-Meier。

## 7. 下一步若要重获检验力（本轮不做）

要让「删失纠正是否有用」可被检验，训练队列必须**真的有相当比例的删失**。
可选路径：

1. **把队列定义放宽到品类 A 之外**，但前提是先能给「在跑 / 失败 / 静默缺失」一个可判定的事件定义。
   这需要生命周期记录，当前数据没有。
2. **缩短近期窗口**，使 T 前 7 天内开始的作业有更大比例尚未完成。
   但这属于改设计，必须**重新预注册**，不能在本轮事后调参。
3. **换一个带完整标签且删失可构造的数据集**，用人为截断（遮住 T 之后的完成时间）
   制造已知比例的删失。这样 oracle 覆盖率已知，信息价值才可谈量级。

第 2 条最省，但必须先把「删失比例」当作设计参数而不是结果，并在选窗口前固定。
