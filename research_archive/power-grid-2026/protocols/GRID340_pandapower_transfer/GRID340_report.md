# GRID340 独立 pandapower 移植试点

原 261 的末批筛选和共享 QP 缓存已经完成判定。按用户决定转向跨仿真平台，直接在 pandapower 3.5.6 CPU Newton–Raphson AC 潮流上接入原 FRAME 搜索、同站补查和等预算全局续查。IEEE 118/300 是 pandapower 自带公开算例，候选为按站枚举的母线分段，LightSim 与 Grid2Op 闭环均未使用。GRID340 的协议、候选范围和原控制规则在首轮潮流前冻结。

3 个工况完成。共尝试 1,546 次 AC 潮流，保存 1,545 条记录，最后失败基线由原日志定位，未搜索该工况候选。固定脚本以基线收敛为前提，失败时未生成汇总 JSON。另用已存反馈重建前三个工况，不重跑任何潮流。两个 118 工况的严格比较接纳少量量级的浮点差异，单精度选择键把这些反馈视为平手。表中的逻辑查询节省来自原全局早停，三臂相同。

跨平台的动作生成、仿真反馈和原 FRAME 决策入口已接通。三个可比较工况同站补查都未触发，因此本批对同站补查增益没有辨识力。当前只具备静态仿真结果，原 261 权重保持在 Grid2Op，整周成本和实际加速未测试。

下一步使用公开的 PGLib-OPF 标准和重载算例。IEEE PES 维护者文档说明，重载组针对线路热限值有约束力的情形。先冻结 IEEE 118/300 的标准与对应重载版，各做一次基线资格，核收敛、电压、设备负载和母线分段入口，再决定是否值得做候选流水线。固定公开算例，不根据已看候选结果挑日期、设定热限或调停止条件。 [IEEE PES PGLib-OPF 说明](https://github.com/power-grid-lib/pglib-opf)
