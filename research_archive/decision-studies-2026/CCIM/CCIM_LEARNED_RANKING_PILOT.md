# CCIM 学习型换点排序小试（预算受限单轮）

**问题（只此一个）**：给定同一批随机抽出的换点候选，学习模型能否把值得查询的换点排到前面，并改善完整搜索的质量—时间表现？

**结论（按预先固定的判定规则）**：**无明确收益 —— 停止这一版学习型排序器，不扩大模型、不追加训练。**

---

## 0. 一句话摘要

在 ca-GrQc（n=5,241，m=14,484，K=4，T=52，batch=32，5,000 次真实扩散查询）上，学习臂的**平均**终值最好（σ 662.0 vs degree 648.0 vs random 633.3），但它在种子 101 上输给 random（640 < 647），因此按事先写死的规则不构成明确收益；墙钟也没有改善。**最需要记录的一条**：pilot 里"学习臂扩散耗时暴涨 47%"是 **torch 前向传播造成的测量假象**，不是搜索在问更贵的问题——用 numpy 复现同一排序后，学习臂每查询扩散耗时回到 random 水平。

---

## 1. 冻结的协议（在线对比前已写定）

| 项 | 值 |
|---|---|
| 图 | ca-GrQc，sha256 `F8CE6E931E068B878044B783DA99EF603F566C87BCBCE7991CD53720879F1660`，n=5,241，m=14,484 |
| K / T | 4 / 52（度前 52 作为初始集） |
| 候选池 | 每状态 52 × (5241−52) = 269,828 |
| batch size | 32（三臂相同） |
| 预算 | 5,000 次查询或 60 秒，先到为准 |
| 接受规则 | 真实 σ 下的**第一个严格改进**的交换；模型**不参与**接受判断 |
| 随机流 | restart / scan 各自独立；三臂一致 |
| 新搜索种子 | **100、101、102**（与训练/验证用的 0/1/2 不重叠） |
| 模型 | 只预测 Δ̂(u,v\|S) ≈ σ(S\{u}∪{v}) − σ(S) |

**批处理框架**：抽 32 个候选 → 只对这 32 个排序 → 按序用真实 σ 验证 → 接受第一个严格改进 → 重建状态与扫描器、丢弃该批剩余候选 → 无改进则取下一批（**不宣告局部最优**）。

## 2. 标签生成（用户要求单列的成本）

问题：ca-GrQc 的三条轨迹此前只存了**每轮扫描**的汇总（`results/candidate_generation_opt.json`），磁盘上不存在任何 `(S,u,v,before,after)` 逐查询行。

做法：用**完全相同**的冻结设置重放种子 0/1/2，这次把每次查询记下来。这不是买新标签——查询数、种子集、接受序列都逐位复现，并由记录的哈希校验：

| 种子 | σ | 查询 | 接受 | 状态 | 行数 | 改进行 | 查询序列哈希复现 | 接受序列复现 | 重放墙钟 |
|---|---|---|---|---|---|---|---|---|---|
| 0 | 635 | 5,000 | 125 | 126 | 4,999 | 125 | ✅ | ✅ | 6.36 s |
| 1 | 650 | 5,000 | 134 | 135 | 4,999 | 134 | ✅ | ✅ | 6.22 s |
| 2 | 638 | 5,000 | 143 | 144 | 4,999 | 143 | ✅ | ✅ | 7.29 s |

- **标签生成成本：19.87 s 重放 + 0.04 s 读图**（`results/swap_records.json`，14,997 行）
- 重放由 `batched_search(batch_size=1)` 驱动，它在单测中被证明与 `ordered_search(random, lazy)` 逐位等价，因此这次重放同时是对该等价性在真实预算、真实图上的再验证。

**标签分布的真实困难**（`results/swap_records_inspection.json`，在线之前测的）：

| 特征 | 与 Δ 的 Pearson | 单独排序的 state 内 pairwise |
|---|---|---|
| `deg_u` | −0.58 | 0.396 |
| `deg_diff` (= deg_v−deg_u) | 0.53 | **0.692** |
| `deg_v` | 0.02 | **0.733** |
| `f1_delta`（单轮阈值代理） | 0.09 | 0.512 |
| `one_round_gain_v` | 0.02 | 0.476 |

- 正例仅 2.5–2.9%（每条轨迹恰好每状态一个正例——扫描在第一个改进处截断）；
- Δ 范围 −586 … +59，方差被"移走高度数种子"的巨额负值主导；
- **`deg_diff` 单特征就有 0.642–0.733**，所以真问题不是"模型能否超过随机"，而是"能否超过这个免费的结构排序"。

## 3. 冻结模型与检查点（含实现审计）

**唯一配置，无超参搜索**（`ccim/learned_rank.py: CONFIG`）：8 维特征 → MLP(32,32) ReLU → 1；损失 = Δ 上的 MSE；Adam lr=0.01，batch=256，max_epochs=40，weight_decay=0；训练种子 20240117；检查点规则 = 验证集 `val_pairwise_accuracy` 最大、并列取最早 epoch。

划分：训练 = 种子 0、1（9,998 行 / 259 正例）；验证 = 种子 2（4,998 行 / 142 正例）。

**训练前发现并修复的两个实现 bug**（属于"实现有 bug 就修好重跑"，不是改选点规则）：

1. **状态 id 跨轨迹碰撞**：三条轨迹的状态 id 都从 1 开始，`collect()` 把多个种子的 `state_sets` 合并进同一个以原始 id 为键的字典，后一个种子静默覆盖前一个，导致前一个种子的每一行都拿**别的轨迹的 S** 去算特征。修复：状态键加种子前缀，且 `build_dataset` 对未知键直接报错。回归测试 `test_states_from_two_seeds_do_not_collide`。
2. **相同 S 未合并**：度前 52 初始集是三条轨迹共同的起点，却被当成三个状态。修复：以 `S` 本身定义分组，`(S,u,v)` 去重。回归测试 `test_states_with_the_same_S_are_merged_into_one_group`。

修复后重跑：**规则仍选中 epoch 1**（val pairwise 0.7454，修复前 0.7365）。**没有手工替换检查点。**

**检查点审计**（`scripts/audit_checkpoint_selection.py`，只查实现、不改规则）：`results/checkpoint_selection_audit.json` → **ALL CHECKS PASS**

- 重载检查点重算验证指标，与报告值逐位一致（0.7453890184439262）；
- **评估模式不可能出错**：网络内不存在 dropout / batch-norm / layer-norm，`train()` 与 `eval()` 无法改变输出；
- 指标与一份独立重实现（不同循环结构）完全一致；对行序不变；
- 参照尺度：model 0.7454 / `deg_v` 0.7327 / `deg_diff` 0.6924 / 随机分数 0.5889 / 机会 0.5；
- 划分在按 `S` 检查下互斥（修复后 403 个状态、0 冲突）；
- 曲线长度、argmax 与冻结规则一致；
- 两次训练产出**逐字节相同**的检查点。

**冻结检查点**：`results/swap_ranker.pt`，sha256 `81e51fac85eb5d8088ef4873d1a64d552ddd1dce53d10984fe3cf20ec2fc4ac3`，epoch 1。

> 标注：**按预注册验证规则选出的模型**，不是"已证明最优的模型"。选择乐观偏差可能存在；它是否有实际价值，正是本轮在线对比要检验的。

**本轮没有做的事**：没有因为曲线看起来不理想而换成最后一个 epoch、平均水平或其它轮次；没有把多个检查点都跑一遍再挑赢家。

## 5. 成本归属：一个必须写下来的更正

pilot 里学习臂的扩散时间 9.15 s vs random 6.09 s（+50%），而模型自身只有 1.16 s。逐条检验（`scripts/attribute_diffusion_cost.py`，`results/diffusion_cost_attribution.json`）：

| 假设 | 测量 | 判定 |
|---|---|---|
| CPU 顺序/争用 | 正序、逆序两遍，代价排序都成立 | **排除** |
| 扩散真的做了更多工作 | 离线重放同一批 trial 统计 `edges_scanned`：8,857 → 9,538，比值 **1.077** | **不足以解释 1.47–1.51×** |
| 被测级联更大 | 平均被测 σ 467.4 → 496.4，比值 1.062 | 同上 |
| GC 停顿被计入扩散计时 | `gc.disable()`：1.8557 → **1.8566 ms** | **排除** |
| **torch 前向本身** | 用 numpy 复现**完全相同**的排序（σ 逐位复现为闸门）：1.8557 → **1.2974 ms**（同一次运行中 random = 1.2611 ms） | **成立** |

也就是说：**"学习臂的扩散贵了 47%"是 torch 前向传播在进程内造成的计时膨胀，不是搜索在问更贵的问题。** 用 numpy 前向的同一排序，每查询扩散耗时回到 random 水平（1.30 vs 1.26 ms），与 `edges_scanned` 的 1.077 比值一致。**具体机制（线程池／频率／分配器）未查明，此处不作断言。**

**修正后的墙钟**（pass D，同一模型、同一排序、numpy 前向）：7.673 / 7.039 / 7.311 s，均值 **7.341 s**。对照 random 6.204 s、degree 7.203 s。
→ 学习臂仍比 random 慢（+1.14 s，其中约 0.67 s 是 32 个候选的特征+排序，其余是略大的级联），与 degree 基本持平。

## 7. 局限（不能说的）

1. **一个开发实例、三个种子。** 新种子只增加重复次数，不构成跨图泛化。任何"论文贡献"级别的说法都不成立。
2. **训练分布有偏。** 重放轨迹在第一个改进处截断，负例来自*被访问过的*候选，而不是候选池的均匀样本。离线 0.7454 的 pairwise 只说明"在这批被访问过的候选上排序得不错"，**不能替代真实搜索表现**。
3. **模型没有学到度结构以外的东西。** 选中的 epoch 1 在验证集上 0.7454，而 `deg_v` 单特征 0.7327、`deg_diff` 0.6924——同一量级。这与"学习臂在线约等于结构基线"的观察一致。
4. **检查点选择。** 验证曲线在 0.54–0.74 之间波动、无趋势；跨 epoch 标准差不是该指标的标准误（各 epoch 共用验证集、模型彼此相关），因此不能据此断定 epoch 1 只是噪声峰值。最高验证分可能存在选择乐观偏差，也不能据此认定所选模型不好。本轮严格按预注册规则使用它。
5. **时间测量对环境敏感。** random 臂每查询扩散耗时在不同批次里从 1.22 到 1.40 ms 漂移；所有时间应按区间读，不按点读。torch 造成的计时膨胀机制未查明。
6. **零缓存复用。** 9 次运行全部 5,000 查询 / 5,000 distinct，所以本轮完全没有触及缓存复用这一维度。
7. **未与任何已发表方法比较。** 这里只有 random、degree（度差结构排序）和一个 DQN 已暂停的分支，不能声称击败 OPIM-C 或任何 CCIM 方法。
