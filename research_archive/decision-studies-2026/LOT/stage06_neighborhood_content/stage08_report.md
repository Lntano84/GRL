# Stage 08：连续搜索何时产出可用改善？

## 研究问题

> EMPTY 的改善通常何时出现？FULL 是否存在更早、且能合法传给 EMPTY 的改善解？

**结论一：EMPTY 的改善出现在后段，而且很晚。** 32 次 EMPTY 连续 40 秒运行**全部**取得了改善，**首次可用改善时间的中位数是 23.70 秒**（注意：这 32 个**运行级**首次改善时间的中位数，与全部 60 个**改善事件**时间的中位数 27.14 秒是两个不同的统计量，不可混用）；rho1.10 组平均 17.07 秒、rho0.75 组平均 29.63 秒。**没有任何一次在 5 秒内产出**（60 个改善事件里只有 1 个落在 5 秒前，只有 12 个落在 20 秒前）。这直接解释了 Stage 07 为什么失败：它拿 5 秒的 EMPTY 当前缀，而在那个时点 EMPTY **什么都还没产出**。此前指定 5 秒缺少产出时间依据，本轮把这件事测清楚了。

**结论二：FULL 没有更早优势。** FULL 在 rho1.10 上首次改善平均 **31.73 秒**，比 EMPTY 的 17.07 秒**更晚**；在 rho0.75 上 FULL **16 次只有 2 次**取得任何改善（EMPTY 是 16/16）。**FULL 在 5 秒、10 秒、20 秒三个检查点上的改善数全部为 0**。严格按端到端 **≤40 秒**计，FULL 两组分别是 **1/16**（rho0.75）与 **15/16**（rho1.10）；另有 **2 个事件发生在约 40.01 秒**（`large_rho0.75_s4|D1_m0_2p` s0、`large_rho1.10_s2|D1_m0_2p` s1），它们**列为超时后事件**并保留在记录中，但**不计入**上述计数。因此不存在"宽邻域更早给出可用解"这回事。

**结论三：FULL 的解无法合法传给 EMPTY。** 在 40 秒检查点上 FULL 优于同期 EMPTY 的 **11 个**情形中，**0 个**满足 EMPTY 的固定条件（违反数 3–4 个短期 Y），**全部 BLOCKED**。按预案，这记为**迁移障碍**：不能直接提交，也不能靠改参考点绕过。

**综合裁决（对应预案第三条）**：**FULL 早期解更好但违反 EMPTY 固定条件 → 记录为迁移障碍**。同时因为 FULL 根本没有早期优势（结论二），预案第一条与第二条也都不成立。**因此"先宽后窄"缺乏依据，本轮不设计该实验。** 亦无启动 GRL 训练的依据。

## 3. 机制：时间花在哪里

某个 EMPTY 运行（`large_rho0.75_s2|D1_m0_2p` s1）的 HiGHS 日志逐段记录：

```
     0       0         0   0.00%   2313.716903     3455.735847       33.05%    12081   1686     0    56713    15.7s
     0       0         0   0.00%   2333.606238     3455.735847       32.47%    10308   1731     0    67648    20.7s
 L   0       0         0   0.00%   2338.01844      2549.755117        8.30%    10936   1729     0    71104    25.0s
 L   0       0         0   0.00%   2338.01844      2511.034173        6.89%    10936   1729     0    81605    29.2s
     2       2         1   0.00%   2338.01844      2511.034173        6.89%    10936   1038     0   113932    40.0s
```

读法（**严格限于日志能证明的范围**，初版把因果说过头了，已收窄）：

- **可以确定的**：primal 栏直到 **25.0 s** 才第一次下降，即**改善出现前，主树根节点附近进行了大量计算**；节点数只有 **2**，说明搜索没有深入树。
- **可以确定的**：日志中两次改善标记都是 **`L`**，即**由 sub-MIP 产出**。
- **不能确定的（初版错误）**：**不能**据此说"根节点的分离/强分支就是根因"，也**不能**说减少这些计算一定会加快改善。前 20 秒的松弛、割平面与其他计算**也可能**帮助了后面那次 sub-MIP 找到解；`L` 标记本身就说明改起来自 sub-MIP，而非主树节点。
- **口径更正**：日志中"对偶界仅提高约 0.9%"对应的是 **15.7 → 20.7 秒**这一段，**不是**整个前 20 秒；`LP iterations` 的**次数也不能直接换算成各部分耗时**（separation / strong br. / heuristics 的单次迭代代价并不相同）。

因此本轮**只主张"5 秒时 EMPTY 什么都还没产出"**（这是观测到的时间分布，第 2 节），以及**"时间主要花在根节点附近"**这一现象描述。至于是不是"根节点计算挤占了产出"，**本轮没有证明**，需要专门实验（例如改变 presolve / 启发式投入然后观察首次改善时间）才能回答，而那属于调求解器参数，本轮不做。

## 4. 结果如何推进下一步

按预先写定的映射逐条对照：

| 预案 | 是否成立 | 证据 |
|---|---|---|
| EMPTY 改善主要在后段，FULL 没有更早优势 → **保留连续 EMPTY，不再尝试颠倒顺序** | **成立** | EMPTY 运行级首次改善中位 23.70 s、无一在 5 s 内；FULL 在 rho0.75 只有 1/16（≤40 s）、在 rho1.10 上更晚（31.73 vs 17.07 s） |
| FULL 确有早期优势，且部分改善解能合法传入 EMPTY → 才设计"先宽后窄" | **不成立** | 5/10/20 s 检查点上 FULL 均未优于 EMPTY；40 s 上优于的 11 例 **0 例可迁移** |
| FULL 早期解更好但违反 EMPTY 固定条件 → **记录为迁移障碍** | **部分命中**：违反属实（11/11 BLOCKED），但"早期更好"不成立 | FULL 的优势只出现在 40 s，且不可迁移 |
| 两者在 40 秒内大多没有改善 → 检查日志中的时间去向 | **不成立**（58/64 有改善），但时间去向已查明 | 改善前大量计算发生在根节点附近；**但这不证明它是根因**（见第 3 节收窄） |
| 不同状态的时间偏好稳定交叉 → 才验证合法信息能否预测 | **未观察到稳定交叉** | 分 ρ 有差异（EMPTY 在 rho0.75 上独占，rho1.10 上 3 胜 1 负），但这不是"时间偏好"的交叉 |

**因此本轮的直接结论：**

1. **保留连续 EMPTY。** Stage 07 的失败不是"顺序选错了"，而是**它切掉的那 5 秒正好是 EMPTY 完全不产出的时段、而它保留的 15 秒又落在 EMPTY 刚开始产出的时段**。20 秒预算下 EMPTY 的产出窗口本来就只覆盖后段，任何"先窄后宽"的切分都会把最有价值的时间让给别的东西。
2. **不设计"先宽后窄"。** FULL 既没有更早的解，其解也不能合法迁移；颠倒顺序缺乏依据，且为接收宽邻域解而改参考点会破坏跨方法可比性。
3. **本轮没有启动 GRL 训练的依据。** 需要先回答"预算该怎么分配"，而本轮证明这个问题的答案不在"邻域内容"或"顺序"里，而在**求解器在根节点附近花了很久才产出第一个改善**这一现象上——但**"根节点计算是根因"尚未被证明**，见第 3 节。

## 5. 边界与诚实注记

- **检查点是前缀，不是独立运行。** 5/10/20 秒的数值读作"该 40 秒运行中在此时刻之前已经找到的最好有效解"，**不能**宣称等同于分别设置 5/10/20 秒截止的独立运行。与 Stage 07 的 E20 做了一致性诊断：**20 秒前缀与 Stage 07 的 E20 交付成本 28/32 相同**（差异来自两批独立运行的求解器噪声，非协议差异）。
- **验解是离线的。** 检查点数值是"到该时刻为止找到的解的质量"，**不是严格实时交付成绩**；模型准备、提交起点与回调开销都**没有**从端到端墙钟里扣除（已同时记录墙钟与求解器时间）。
- **未证明存在统一时间阈值。** 本轮给出的是"EMPTY 的改善集中在 14–36 秒"这一**观测分布**，并**受 40 秒窗口右截断**——58/60 个改善事件落在 40 秒内，无法排除更长窗口下还会继续出现改善，也不能断言"必然需要 X 秒"。因此"5 秒太短"是确定的，"至少需要多少秒"仍未测。
- **"根节点计算挤占了产出"未被证明。** 日志只能证明改善出现前在根节点附近做了大量计算，且两次改善均标记为 sub-MIP（`L`）产出；由此**不能**推出"减少这些计算就一定更快改善"。另外，"对偶界提高约 0.9%"只对应 **15.7 → 20.7 s** 一段（不是整个前 20 秒），`LP iterations` 的**次数不能换算成各部分耗时**。
- **统计口径要分开**：32 个 EMPTY **运行级**首次改善时间的中位数是 **23.70 s**；60 个 EMPTY **改善事件**时间的中位数是 **27.14 s**。两者不是同一个量。
- **超时后事件单列**：严格按端到端 ≤40.00 s 计，FULL 两组为 1/16 与 15/16；另有 2 个 FULL 改善事件发生在 40.01 s，保留在记录中但列为超时后事件，不计入改善计数。
- **存在一次异常早的事件**（`large_rho1.10_s4|D2_all_1p` s1，0.12 秒）。它经独立验解确认可行且优于修复，未发现异常，但单独一例不能改变分布结论。
- **rho0.75 上 FULL 只有 2/16 改善**是"宽邻域在该组更难产出"，但本轮**不能**确定原因（可能是该组实例的搜索更难，也可能是宽邻域带来的分支规模问题）。
- 结论限于 **large 尺度、40 秒窗口、highspy 1.15.1、numpy/scipy 版本同 Stage 07**。
- 未做参数扫描、未训练模型、未生成新实例。
