# GRID00：Grid2Op / L2RPN 首轮资格检查

日期：2026-10-08。裁决：**指定 IDF 环境的短轨迹与接口检查通过；强基线仍未运行；研究价值尚未判定。**

本轮已实际安装并运行，不是仅查阅资料。未训练模型、未生成教师标签、未下载完整研究数据。原仿真进程在全部轨迹和复现检查完成后的一项附加诊断中退出码为 1；该错误和离线收尾在第 4 节完整披露，不能写成“原程序零错误退出”。

## 1. 研究对象与现实边界

选定 `l2rpn_idf_2023`，因为 La Javaness 的 LJN 2023 发布动作资产与该电网匹配。不能把其训练资产直接搬到较小电网，再宣称复现了同一强基线。

具体任务是：每 5 分钟根据电网观测、允许的负荷/发电预测及静态网络模型，决定拓扑、线路、再调度、储能和限发操作，在原生操作限制、故障/检修及攻击机制下维持运行并控制运营成本。动作可行性、冷却时间、过载断线和 AC 潮流由环境实现；正式实验仍须冻结评价指标和计算预算。

这是有电力行业背景的公开仿真任务。IDF 数据建立在修改过的 IEEE 118 节点网络与法国 2035 能源结构情景上，**不是实际法国电网实时控制或真实现场运营日志**。官方完整环境约 5.4 GB、832 个周场景；本轮只用软件包随附测试数据，不能替代完整数据的封存评价。[官方环境说明](https://grid2op.readthedocs.io/en/latest/available_envs.html)

## 2. 已运行的范围与结果

| 项目 | 实测结果 |
|---|---|
| 隔离环境 | Python 3.12.14；Grid2Op 1.12.5；LightSim2Grid 1.1.0；PandaPower 3.5.6 |
| 电网 | 118 变电站、186 线路、62 发电机、99 负荷、7 储能 |
| 随包数据 | 2 个测试场景，完整文件哈希已保存；实际只执行 `2035-01-15_0` |
| 接口控制 | DoNothing、RecoPowerline 各重复两次，共 4 条×24 步＝96 个实际步 |
| 复现 | 各方法两次运行的全部观测、动作、奖励、终止和错误标志完全一致 |
| 原生判定 | 96 步中 illegal 0、ambiguous 0、异常步骤 0，均未终止 |
| 预测调用 | 初始状态分别调用 horizon=1、12，均返回有效结果；没有测试所有中间时距 |
| 状态隔离 | 初始状态、do-nothing、horizon 1/12 两次调用后，当前观测、线路起点信息数组与实际步号均不变；高精度模拟计数依次 0→1→2 |
| 时间 | 首次导入 8.116 秒；建环境 1.225 秒；导入后直到收尾错误共 3.667 秒；父进程总计约 12.25 秒 |

默认搜索奖励为 `RedispReward`，本轮没有改成 LJN 使用的 `MaxRhoReward`，因此不作 LJN 复现声明。

这 24 步前缀很平稳：四条轨迹的步骤最大 `rho` 均为 0.980458，两个控制器行为相同，Reco 没有产生模拟搜索调用。因此通过的是**重置、步进、记录和预测调用接口**，不包括复杂拓扑/再调度动作的实测资格，不支持生存率、控制质量或预测误差的研究结论。原生动作键包含 `set_bus/change_bus`、线路状态、redispatch、curtail、storage、alert；这些是权限清单，不是已逐动作验证。`RulesByArea` 的区域限制不能误读为全网单一限额。

两个预测调用使用了合法预测接口，不读取实际未来轨迹。环境 API 也提供更长预测和应力测试；“增加前瞻/候选模拟”本身已有官方用法，不构成新意。[官方规划接口](https://grid2op.readthedocs.io/en/latest/model_based.html)

## 3. 强基线检查：已定位，但未运行通过

只读获取 LJN 仓库的 10 个文件，固定 commit `ca0637eab9f098be7f206ed0e46a3900cd4deec0`，保存来源与 SHA-256，代码许可证为 MPL 2.0。这是源码检查子集，不是完整安装包。作者将其描述为 L2RPN 2023 获胜方案的重构版本；本轮不把它称为截至 2026 年的最强方法。[作者仓库](https://github.com/lajavaness/l2rpn-2023-ljn-agent)

| 项目 | 当前结论 |
|---|---|
| 电网/动作资产匹配 | 作者明确指定 IDF 2023；未下载动作或模型资产，未核对动作向量维度 |
| 搜索组成 | 拓扑候选搜索、重连、恢复拓扑、连续优化组合；存在 NN Top-k 版本 |
| 信息权限 | 读取区域映射及后端静态线路/变压器参数，公平对照应拥有相同权限 |
| 搜索奖励 | 按模拟奖励排序；复现须使用作者指定奖励，最终评价另行明确 |
| 计算成本 | 一次 `act` 可能触发很多次模拟，必须计入动作构建、预测、优化和模拟总成本 |
| 兼容性 | `np.NaN` 在当前 NumPy 2.4.6 已移除；源码构造函数仍使用。原版不能直接标为可运行 |
| 发布入口 | `evaluate.py` 的构造参数次序与 `LJNAgent` 签名相反；需要核对推荐工厂入口，不能盲跑 |

最重要的研究收窄：优化模块已含安全余量、上一轮计算潮流与观测潮流之差的校正（`convex_optim.py` 的 `alpha_por_error`、`_prev_por_error`、`flow_computed`）。**不能声称“现有强方法完全不使用误差信息”，也不能把加入历史误差当作已确认的新贡献。** 该校正的具体作用和未覆盖条件仍须实测。

作者报告原动作集教师搜索使用约 128 CPUs ×5 天；后续应复用公开资产并披露其来源，不在笔记本上重新生成。资产的离线来源不能隐去，也不能要求便宜对照在没有这些资产的条件下竞争。

## 4. 错误、修正与审计边界

1. 隔离环境最初的 ensurepip 因默认临时目录权限失败；将 TEMP/TMP 指向本工作区后成功，未改变全局环境。安装辅助脚本首次用 Windows 默认 GBK 读 pip 的 UTF-8 JSON，改为显式 UTF-8 后成功。均发生在仿真之前。
2. 4 条轨迹、两次预测检查、NPZ 和复现检查均已保存。之后附加的“预测向量减实际向量”报错：两者维度分别为 4712 与 4460。不能不对齐字段就相减，不能据此测量预测误差。原源文件保留为 `probe_original_vector_compare.py`，错误日志与 `failure.json` 保留。
3. 修正后的 `probe.py` 只记录两类向量形状，**没有重跑仿真**。`audit_saved.py` 离线核对 96 步的日志/NPZ 哈希、重复轨迹、奖励标志、资产哈希及模拟计数，退出码 0，生成 `GRID00_audit.json`。没有删除轨迹、改动作或调环境。
4. 该审计是保存数据的一致性复核，**不是另一套 AC 潮流器的独立物理验解**；模拟前后状态不变的判断由运行时断言及日志记录，后验只复核记录。检查不覆盖所有动作、所有 horizon 或完整隐藏内部状态。第二名审查代理只读核对代码与记录，未发现推翻这一限定结论的问题，没有额外调用仿真。

## 6. 研究判断与下一步

**值得继续完成强基线资格，尚不值得启动 GRL。** 平台有公开业务背景、可用模拟器和匹配的成熟对手；当前缺口仍未建立。

2026 年文献已经比较 AlphaZero/MCTS 控制和 PPO，也有图表示的专门对比研究。前者报告无学习引导 MCTS 在其设置中能提升训练效率；后者是投稿中的预印本，不能当成已接受的会议论文。因此“GNN+RL 控制电网”“更丰富图结构”“先搜索再模仿”均需具体区分，不能直接作为新题目。[AlphaZero 研究](https://arxiv.org/abs/2608.14114)、[图表示对比预印本](https://arxiv.org/abs/2609.02538)

下一步仅做 **GRID01：LJN 强基线接入与一次有界运行诊断**，先给半天工程上限，不扩展成重建基准：

1. 同 commit 补齐代码与推荐非 NN 工厂所需的 IDF 动作资产，核对向量维度、哈希和许可证；复用作者资产，不重训。优先跑非 NN 混合方案，非擅自删减后的弱替代品。
2. 明确适配补丁与包版本。把行为修补和纯兼容修补分开；若需要改决策逻辑，暂停原版复现主张。
3. 固定作者搜索 reward、原生动作权限、区域规则、静态模型访问和求解器参数。记录端到端 `act` 时间、模拟调用数、连续求解状态与各模块触发；不靠修改线路限额制造困难。
4. 在两个随包测试场景上做固定短前缀，仅回答是否能运行、成本如何、各模块是否触发。仍不把这两条公开测试场景用作泛化/论文主实验。
5. 只有强基线可运行且存在可记录的失败/额外开销，才冻结后续失败分类与研究假设。失败可能来自预测误差、候选覆盖、操作冷却、连续优化或动作组合，不能预先统一解释为“缺少学习”。

**本轮没有发现学习优势，没有给出投稿概率；也没有得到否定该领域的结果。** 目前跨过的是可用环境这一步，强基线与可研究缺口是下一步。
