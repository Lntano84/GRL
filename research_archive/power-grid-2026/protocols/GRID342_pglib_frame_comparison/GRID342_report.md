# GRID342 PGLib-OPF IEEE118 同站补查对照

在 GRID341 两个收敛的 IEEE118 工况上，对固定的 642 个候选各评价一次。沿用原调度、支路数量、Rate A、电压窗口和候选顺序。保留原 128/64、停滞 2、0.9 门控和严格可行条件。用相同保存反馈比较全局早停、同预算全局续查、FRAME 和穷举。各工况编号 98、477 的候选会断连，保留原序位置与失败标记，无 AC 求解。

| 工况 | 原基线最大负载率 | 电压合格候选中的最低最大负载率 | 严格可行动作 | 各臂查询位置 | 同站补查 |
| --- | ---: | ---: | ---: | ---: | ---: |
| IEEE118 标准 | 196.70% | 169.80% | 0 / 642 | 642 | 0 |
| IEEE118 API 重载 | 426.09% | 298.36% | 0 / 642 | 642 | 0 |

标准版 640 个 AC 候选均收敛且电压合格，全部仍超热限。API 版 595 个候选收敛、电压合格但仍超热限，42 个落在电压或有限性门外，3 个不收敛。四臂均用尽序列且未返回动作。最好的电压合格候选相对各自起点降峰 13.68% 和 29.98%，仍超原限值，因此仅作动作库诊断。标准版最重支路保持原索引 118，API 最佳候选的最重支路改为原索引 115。两条 IEEE300 的基线失败沿 GRID341 留存。

最终保存 1,284 个候选位置，其中 1,280 次 AC、4 个断连预检。运行约 39.17 秒是一次枚举墙钟，各臂计数是逻辑查询位置。独立只读复核逐行对应库索引、各类失败、四臂查询与最佳诊断值。零基线重算、零训练、零 OPF 或新 Grid2Op 步。

这两个公开重载工况下，现有单站小动作库无法满足严格热限。为空的可行集合使试验无法比较同站补查增益。关闭直接使用这批 PGLib 给定运行点的路线。下一轮只做有限来源核对，寻找公开且已有可复现调度和额定值的拥塞工况，先验证存在接近可行的操作区间再考虑动作比较。当前原 261 及主表保留。
