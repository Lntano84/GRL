# Stage 09B：哪个变量组值得释放？

## 唯一问题

> 从连续最优的共同起点出发，只允许改变哪些二元变量组，能够在 20 秒内获得额外收益，并超过完整 EMPTY？

**结论：`AB`（远期 Y + 短期 Z）是明确的变量组选择结论。** 它在 **8/8 个名义实例**上都优于完整 EMPTY（ABC），平均 **+12.92%**，在两个求解器种子上方向完全一致（8/8）；并且 `C`（远期 Z）作为"额外自由度"是**有害**的——ABC 比 AB 差，说明在 20 秒预算下把 C 也放开会**降低**搜索效果。

**交付结论是一句话**：在这套模型与 20 秒预算下，应当释放 **A = 远期 Y** 与 **B = 短期 Z**，并**保持 C = 远期 Z 固定**。这是一个**非学习的算法基线**，不是学习器。

---

## 1. 冻结设置

| 项目 | 安排 |
|---|---|
| 状态 | 原有 **16 个 large 故障状态** |
| 变量组 | `A = {Y_ijt : t > τ}`、`B = {Z_ijt : 1 ≤ t ≤ τ}`、`C = {Z_ijt : τ < t < T}` |
| 组大小 | A = 864、B = 432、C = 792（`Z_ijT` 与 `Z_ij0` 结构固定，任何配置都不释放；短期 Y 任何配置都不释放） |
| 配置 | `A B C AB AC BC ABC`（ABC = 完整 EMPTY）＋ `LP` 基线（Stage 09A，无需新运行） |
| 未释放二元变量 | 固定为 **S_r 的规范化值**（整数容差先检查，实测最大规范化误差 1.77e-14） |
| 起点 | **每个 MIP 都从 Stage 09A 的同一 LP 解 `S_LP` 启动** |
| κ / 固定条件参考 | **始终是 S_r**，不重新定义 |
| 预算 | 每次 **20 秒**，**包含 LP 初始化与方法准备** |
| 运行 | 16 × 7 × 2 = **224 次 MIP**（wall 2785 s ≈ 46 分钟） |
| 切分/重启/参数 | **无** |

**避免再次出现共享前缀计时问题**：每次逻辑运行**各自重跑**那个廉价 LP（约 0.1 s），把剩余预算交给 MIP。核验结果：**224/224 次 LP 目标值与 Stage 09A 一致**，MIP 授予预算 19.96–19.98 s。

**输出规则**：最终交付取**有效候选中最好者**，候选集至少含 **{solver incumbent, `S_LP`, `S_r`}**。实测 **224/224 由 solver 胜出**（即 MIP 在 LP 之上确有改善），从未退回到较差的 `S_r`。

**抽样完整性**（`stage09b_savecheck.py`，不重新求解）：224 个交付方案全部重新验证——原模型可行、κ 相对 `S_r`（短期翻转 ≤ 4）、**未释放的二元变量确实仍在 `S_r` 处**（这是配置之所以成立的**定义性条件**）、短期 Y 在任何配置下都未移动、结构固定的 `Z_ijT` 未移动、各组翻转计数与方案一致、输出规则确实返回最优有效候选、预算守恒。**最大约束违反 0**。

## 2. 主指标

两个指标都用**原来的状态级分母** `max(1, |J_r|)`，先逐 (状态, 种子) 计算，再对 2 个故障 × 2 个种子平均得到 8 个名义实例。**没有**"从全体均值里统一扣掉 5.34%"，也**没有**逐实例挑最优配置冒充策略。

```
G_extra(a)    = (J_LP  − J_a) / max(1, |J_r|)      扣除连续重优化后的额外收益
G_restrict(a) = (J_ABC − J_a) / max(1, |J_r|)      限制类别是否优于完整 EMPTY
```

**`AB` 的种子方向稳定性**：8 个名义实例上 seed0 与 seed1 **方向全部一致（8/8）**，例如 `rho0.75_s3` 为 +0.3417 / +0.3455、`rho1.10_s5` 为 +0.0280 / +0.0378。**不是单个种子造成的。**

### 廉价替代方案必须纳入基线：`BC`

`B`、`C`、`BC` 三个配置**全部在 5 秒 LP 之后立即证得最优**，因此它们的运行时间本身就是结果：

| 配置 | 证最优 | 平均总耗时 | `G_extra`（超 LP） |
|---|---:|---:|---:|
| B | 32/32 | 0.32 s | +0.0409 |
| C | 32/32 | 0.24 s | +0.0196 |
| **BC** | **32/32** | **0.92 s** | **+0.0611** |

**`BC` 用不到 1 秒取得了 `G_extra` = +6.11%**（其中 28/32 次严格优于 LP）。对照 `AB` 的 +17.39% 需要 20 秒满预算（0/32 证最优）。**这个质量—时间权衡是本轮报告必须保留的结果**：`AB` 相对 `BC` 的额外收益要付出约 20 倍的求解时间，`AB` 的额外计算是否值得，需要按这个口径评估，而不是只看 `G_extra` 的高低。

**注意**：`BC` 的 `G_extra` 是 **+6.11%**（相对 LP），而它的 `G_restrict`（相对 ABC）只有 **+1.64%**——两个数不能混用。

### 来源与改善必须分开统计

`final_source = solver` **并不代表严格改善**：在 224 次运行中，solver 胜出的是全部 224 次，但其中**严格优于该次 LP 的只有 172 次**（另有 52 次与 LP 完全相同，21 次为精确相等）。逐配置的严格改善数：

| 配置 | 严格 < LP | = LP |
|---|---:|---:|
| A | 32/32 | 0 |
| **AB** | **32/32** | 0 |
| BC | 28/32 | 4 |
| B | 24/32 | 8 |
| C | 20/32 | 12 |
| ABC | 13/32 | 19 |
| AC | 13/32 | 19 |

（判定容差 1e-9 相对；**没有任何一次运行的结果劣于该次 LP**。若把 1e-4 相对以内的差异也算作持平，严格改善数为 172；本报告统一采用 1e-9 相对口径。）

## 3. 研究空间分解（同一分母）

| 项目 | 数值 |
|---|---:|
| 连续 LP 相对 S_r 的改善 | **+0.0534** |
| **ABC（完整 EMPTY, 20 s）超出 LP 的额外改善** | **+0.0447** |
| ABC 相对 S_r 的总改善 | +0.0981 |
| **AB 超出 LP 的额外改善** | **+0.1739** |
| AB 相对 S_r 的总改善 | **+0.2273** |
| 参考：E@40 超出 LP 的额外改善 | +0.1561 |

分母都是 `|J_r|`，**不是最优性损失，也不是"全部潜在收益"的比例**。

两个可直接读出的结论：

1. **`AB` 的总改善（+22.73%）在数值上超过 40 秒轨迹前缀 E@40 的总改善（+20.95%）。** 但这**只能作历史描述**：两者**起点不同**（AB 从 LP 解启动、E@40 从 S_r 启动），因此**不能**据此单独断定"瓶颈不在预算总量"。
2. **ABC 只比 LP 好 +4.47%，而 AB 好 +17.39%**：在**相同起点、相同预算**下，多释放 C 净损失约 **12.9%**。这才是本轮有力的比较。

## 4. 机制：为什么 AB 更好，C 为什么有害

**所选方案实际改动的变量组**（每配置 32 次运行的平均）：

| 配置 | 释放数 | 改动 A | 改动 B | 改动 C |
|---|---:|---:|---:|---:|
| A | 864 | 58.8 | 0.0 | 0.0 |
| B | 432 | 0.0 | 5.2 | 0.0 |
| C | 792 | 0.0 | 0.0 | 11.8 |
| **AB** | 1296 | **57.7** | **5.5** | 0.0 |
| AC | 1656 | 31.8 | 0.0 | 21.9 |
| BC | 1224 | 0.0 | 5.4 | 11.3 |
| **ABC** | 2088 | **32.5** | **1.5** | **22.4** |

三处可读的事实：

1. **A 是主要的收益来源**：单独释放 A 就拿到 `G_extra` = +14.90%，且 32/32 次都由 solver 胜出、A 组平均改动 58.8 个变量。这印证了 Stage 09A 的结构统计（EMPTY 的改善主要伴随远期 Y 变化）。
2. **B 小但真实有用**：`AB` 比 `A` 在 **7/8 个实例**上更好（唯一例外是 `rho0.75_s4`，−0.15%），平均 **+2.49%**。`AB` 相对 `A` 的优势是本轮最强的次要证据。
3. **C 改变了搜索表现**（方向是变差），但**原因尚未确定**。

**三条必须收窄的表述**（初版说过头了，已改正）：

- **不能说"C 抢占了 B 的搜索资源"。** 上表的变量改动次数是**最终解**的属性，**不是搜索过程的资源分配记录**。观测到的事实只是：开放 C 改变了搜索表现（AB 与 ABC 在相同起点、相同预算下有实质差距）。至于是不是"把活动从 B 转移到 C"，本轮**没有**过程数据支持（回调轨迹只记录了 Stage 08 的 EMPTY/FULL，不是本轮的 ABC 与 AB）。
- **不能由 `G_A + G_B > G_AB` 证明作用重叠。** A 与 AB 都**未证最优**（0/32 证最优），这个不等式可能同时受限时求解影响，不构成任何关于"作用重叠"的证据。可说的只是：B 在 A 之外**仍然带来收益**（7/8 实例）。
- **AB(20 s) 与旧 E@40 的比较只能作历史描述。** 两者**起点不同**（AB 从 LP 解启动，E@40 从 S_r 启动），因此那个比较**不能**单独证明"瓶颈不在预算总量"。本轮真正有力的是**同起点、同预算**的 **AB—ABC** 比较。

**这不是数学上的互补性或必要性。** 目标值未收敛，AB 与 ABC 的差距是**限时求解下的组合效果**。**加入 C 改变了搜索表现**（这是观测事实）；至于**为什么**，本轮**尚未确定**——可能是搜索资源分配的改变，也可能是别的原因，而最终解的变量改动次数**不是**过程记录，无法用来判定。给 ABC 更多时间，它可能追上甚至超过 AB——本轮的证据**不能**排除这一点（ABC 在 4/8 实例上仍严格优于 LP，说明它并非完全无效）。

## 5. 结论与下一步

**本轮交付的变量组选择结论**：在**这套模型、large 尺度、20 秒预算、这批开发实例**下，应当释放 **A（远期 Y）与 B（短期 Z）**，并**保持 C（远期 Z）固定**；`AB` 在每个名义实例上都优于完整 EMPTY，种子方向 8/8 一致。

**但这仍是开发集证据，尚未独立确认**（Stage 10 用新实例种子 6–13 做冻结确认）。

按预案逐条对照：

| 预案 | 是否成立 | 证据 |
|---|---|---|
| 某个固定子集稳定超过 ABC → 得到值得推进的非学习算法基线 | **成立** | `AB` 8/8 实例优于 ABC、31/32 配对、种子方向 8/8 一致 |
| 不同实例需要不同子集且选错有实质损失 → 才有状态条件选择的研究依据 | **不成立** | `AB` 无需按实例切换；没有观察到"不同实例要不同子集" |
| ABC 最好、限制类别没帮助 | **不成立** | 限制类别**大幅**有帮助（+12.92%） |
| 所有配置都停在 LP 成本 | **不成立** | 无配置在所有实例上停住 |
| 较小子集已取得收益 → 是该子集**足够**的证据 | **成立** | `AB`（1296 变量）已取得大部分收益；但这**不**证明 C 不必要 |

**下一步（本轮不做）**

1. **在未参与方案选择的新 large 实例上冻结确认 `AB`**（Stage 10）。目前它是**非学习基线**——学习优势与论文新意**仍未建立**。
2. **本轮先不拆 `Z_τ`。** 按时间位置细分 B 是合理的机制假设，但在独立确认前增加变体，会把刚获得的清晰候选重新变成配置搜索。
3. **不要**据此宣称需要更精细的学习器；也**不要**把"ABC 更差"读成"C 数学上无用"。

## 6. 边界

- **限时组合效果，不是数学结论**：目标值未收敛（大部分 20 s 运行以 `Time limit reached` 结束），AB 与 ABC 的差距是**20 秒内的搜索效果差异**。给 ABC 更多时间它可能追平或反超；**本轮的"释放 C 有害"仅指 20 秒预算下**。
- **较小子集限时失败不能证明它不够**：同理，`C` 单独 +1.96% 不构成"C 无用"，`AB` 的优秀也不构成"C 不必要"（无最优值或有效下界支持）。
- **ABC 在 4/8 实例上仍严格优于 LP**，因此完整 EMPTY 并非无效，只是在本预算下不如 AB。
- `G_extra` / `G_restrict` 都是相对 `|J_r|` 的**相对差**，**不是最优性间隙**。
- 每个状态的二元配置仍只来自 **S_r 一条分支**；本轮不枚举其他配置。
- 起点固定为 Stage 09A 的 LP 解；**从 `S_r` 启动的旧 EMPTY 结果只作历史参考**，本轮公平主对照是同样经 LP 初始化的 ABC。
- 结论限于 **large 尺度、16 个冻结状态、该模型与成本口径、20 秒预算、highspy 1.15.1 单线程**。
- 未调求解器参数、未切分预算、未重启、未训练模型、未生成新实例。
