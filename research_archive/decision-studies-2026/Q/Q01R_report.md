## 2. 正确的机制

固定 `b = 10`，**截止值即容忍度**：

| cap | 隐藏 x | x ≥ b | x ≥ cap | `mask` | `explored_m` | `timeout_m` | 计入预算 | 之后仍可作候选 |
|---:|---:|:--:|:--:|---:|---:|---:|:--:|:--:|
| 2 | 5 | False | True | 0 | 0 | 2 | False | True |
| 2 | 20 | True | True | 0 | 1 | 2 | False | False |
| 10 | 5 | False | False | 1 | 1 | None | True | False |
| 10 | 20 | True | True | 0 | 1 | 10 | False | False |

**读法：**

- `cap = 2`：两个真值**都正确记为超时**、都只收 2 秒。它们的差别**只在 `explored_m`**：
  x=5 保留候选资格，x=20 被淘汰。**而这个差别由隐藏真值决定——「超过 2 秒」并不能揭示它。**
- `cap = 10`：x=5 完成、x=20 超时，**这两行状态不同是合法的**。我上一轮把这一行当成了「已在 2 秒被取消」。

**所以真正的问题是不可观测的候选淘汰**（[limeqo.py:89](Q01_work/limeqo_mirror/src/strategies/limeqo.py)），
不是完成标签错记。这不证明论文成绩的影响量级。

### 2.1 隐式重跑路径

目标单元格真值 x = 5，当前最好值 b = 10：

| 轮次 | cap | 分支结果 | 收费 | 累计 |
|---|---:|---|---:|---:|
| 1 | 2 | `mask=0, explored_m=0, timeout_m=2` | 2 秒 | 2 秒 |
| 2 | 10 | `mask=1, explored_m=1, timeout_m=None` | 5 秒（**从头重跑**）| **7 秒** |

总计 **7 秒**。所以正确表述是：

> **没有单独命名的重试动作，但存在超时候选再次执行的路径；这条路径的资格受隐藏真值影响。**

另外，`timeout_m` 会通过预测模型间接影响候选分数，因此**不能因为过滤器没有直接读取它，
就断言它不影响后续选择**。

**对选题定位的影响：** 我们**不能**再把「引入重试」当作相对现有实现的新功能。
仍然开放的是**何时重跑值得它的成本**——这一条现有实现没有显式决策。

判据：**这次读取是否超出了该次执行本身所能揭示的信息。**

| 类别 | 位置 | 说明 |
|---|---|---|
| **违规：候选淘汰** | `limeqo.py:89`、`limeqo.py:114`、`limeqo_plus.py:114`、`limeqo_plus.py:139`、`greedy.py:74`、`random.py:60`、`qo_advisor.py:68` | 用未揭示的比较（x ≥ b）决定资格 |
| **违规：特权停止** | `limeqo.py:35`（`min_observed.sum() > opt_time + 20`）、`limeqo.py:105`（`opt_time + 50`）| `opt_time` 是**完整隐藏矩阵**的逐行最小值，即 oracle 最优；可用于事后评价，**不能作为可部署停止条件** |
| **合法：完成判定** | `limeqo.py:92`、`limeqo_plus.py:117` | 判定刚执行的那次运行在所给 cap 下完成还是超时；环境必须知道它才能报告反馈种类 |

上一轮报的「9 处」这个计数**撤回**；上表才是需要区分的。

**对固定预算比较的直接要求：** 必须去掉特权停止规则。这不自动使此前所有轨迹前缀失效，
但固定预算的对照实验不能沿用 `opt_time` 作为停止条件。

## 4. 最小反馈接口

```text
observe(query, hint, cap) -> kind, value_or_bound, charged_seconds

kind == 'completed' : 在 cap 内完成，value_or_bound 为实际耗时
kind == 'cancelled' : 在 cap 被停止，只揭示 'runtime >= cap'，收费 cap
```

沿用原代码的边界约定：**`x < cap` 为完成，`x >= cap` 为超时**。重跑**从头计费**。
策略对象**不持有真实矩阵**；环境持有它（因为必须据它生成反馈），但只暴露上面这个三元组。

实现见 `Q01_work/q01r_interface.py`（`ReplayEnvironment` + `LegalPolicy`）。

### 4.1 四项确定性检查（全部通过，未拟合任何预测器）

| 检查 | 要求 | 结果 |
|---|---|---|
| 1 | `b=10, cap=2, x∈{5,20}`：合法反馈相同，合法策略状态相同 | **通过**：两者都是 `('cancelled', 2, 2)`，状态逐字段相同 |
| 2 | `b=10, cap=10, x∈{5,20}`：分别完成与超时，允许状态不同 | **通过**：x=5 → `('completed', 5, 5)`；x=20 → `('cancelled', 10, 10)` |
| 3 | `x=5`，先 `cap=2` 再 `cap=10`：先超时后完成，总成本 7 | **通过**：2 + 5 = **7**，且首次超时后仍具资格 |
| 4 | 只改未揭示真值与全矩阵最优值：下一动作与固定预算停止判断不变 | **通过**：两个世界的下一动作均为 `(0,1)@cap2`，`stop_by_budget` 均为 False |

**检查 1 中原分支的差异作为「被捕获的历史缺陷」保存**，写在 `q01r_checks.json` 的 `official_defect_differs` 字段里，**不写成合法实现应有的行为**：
原分支对 x=5 置 `explored_m=0`、对 x=20 置 `1`，尽管两者给策略的反馈完全相同。

检查 4 正是官方停止规则**通不过**的那一项：它读 `opt_time`。

### L2 官方成本与等价传播：**缺失**

- **计划等价类来自 EXPLAIN 计划包（Dropbox），矩阵 CSV 不含它。**
  没有它，回放无法复现「观测一个 hint 覆盖整个等价类」的效果。
- **初始掩码不只是第 0 列。** 四个数据集分别有 **38 / 51 / 42 / 36** 个已标记单元格的
  数值与所在行第 0 列不同（且全部位于第 0 列之外）：

| 工作负载 | 已标记 | 其中第 0 列 | 其中非第 0 列 | 数值 ≠ 本行第 0 列 |
|---|---:|---:|---:|---:|
| ceb | 9,539 | 3,133 | 6,406 | **38** |
| job | 607 | 113 | 494 | **51** |
| stack | 33,312 | 6,191 | 27,121 | **42** |

  这不证明初始化有问题，但意味着**不能把整个初始掩码解释成默认计划的免费等价传播**。
  **来源与初始化成本必须明确。**

## 6. 初始化与等价类的待办边界

本轮的小检查**使用人工给定的等价类**（把每个 hint 视为自成一组）。
**不通过运行时间相等来推断真实计划等价**——列完全相同的现象与等价结构一致，
但相等也可能是巧合。本轮**不下载完整计划包、不重建数据库**。
