## 1. 关键发现：归一化不是普通的 BatchNorm，而且**没有跨样本耦合**

你指到 `dqn.py:84` 是对的。原文：

```python
def apply_bn(self, x):
    ''' Batch normalization of 3D tensor x '''
    bn_module = nn.BatchNorm1d(x.size()[1]).to(self.device)
    return bn_module(x)
```

调用处 `gcn_forward`（`dqn.py:97-117`）传入的 `x` 形状是 **`(batch, num_nodes, features)`**，所以：

1. `x.size()[1]` = **num_nodes**，即通道数是**节点数**，不是特征数；
2. `BatchNorm1d` 对 3D 输入 `(N, C, L)` 在 **N 与 L** 上统计、按通道 C 归一化。逐样本循环里 **N = 1**，所以它实际是：**对每个节点，仅沿特征维求均值/方差**；
3. `bn_module` 是在**每次调用内部新建**的，因此**从不累积运行统计**——这就是我们早先观察到 `num_batches_tracked = 0` 的原因；
4. 新建模块的仿射参数是默认的 `weight=1, bias=0`，等价于恒等仿射。

**结论：该归一化对每个 (样本, 节点) 独立计算，不存在任何跨样本或跨节点的耦合。**

这一点很重要，而且方向是**乐观**的：它意味着批量版**可以**做到逐位等价——只要批量版把归一化按「每个 (图, 节点) 沿特征维」来算，而不是对整个 padded batch 一起算。

## 2. 因此「朴素批量化」会破坏什么（你的判断成立）

若直接把 B 张图 padding 后堆成一个 batch 调 `apply_bn`：

- `BatchNorm1d(M)`，N = B，于是均值/方差在 **(B, features)** 上求，**同一批里的图会进入彼此的统计量** → 与你指出的完全一致；
- 更糟的是，原始实现按**每张图各自的节点数** `m_i` 建通道（`BatchNorm1d(m_i)`），批量版统一成 `M` 后，连通道数都对不上；
- 填充节点还会进入 `torch.max(embedding_tensor, dim=1)`（`dqn.py:245`、`278`）、进入 `F.softmax(..., -1)` 的赋值张量（`dqn.py:257`）以及 `matmul(assign^T, embedding)`（`dqn.py:269`）。

## 3. 批量版必须满足的规格（供实现与验证）

1. **归一化**：对每个 `(b, i)` 独立，沿**特征维**做 `(x - mean) / sqrt(var_biased + 1e-5)`，只在该图的有效节点 `i < m_b` 上计算；填充位置输出 0。**不得**对 batch 维求统计。
2. **池化与最大值**：`max` 前把填充节点置 `-inf`；`dqn.py:245 / 278` 两处都要处理。
3. **池化赋值**：`softmax` 的 logits 在填充位置置 `-inf`（或算完后把填充行清零），保证 `assign^T @ embedding` 与 `assign^T @ adj @ assign` 不受填充影响。
4. **邻接**：padding 后的 `adj` 行/列全 0，且 `graph_conv` 里 `matmul(adj, x)` 天然不会把填充节点的值传播进来（因为列被置 0），但归一化与池化仍需按 1–3 显式屏蔽。
5. 以上四点做完后，**仍须**用固定混合 batch（16–63 节点）对照逐样本版的 `state_embed`、`node_embeddings`、两个 Q、损失、梯度、连续更新后的参数与动作选择。
