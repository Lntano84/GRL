## 3. 实现 `repair_minbatch_v1` 时发现的两个结构问题

第一版修复器产出**不可行**计划，独立验解器立刻报出 `activation` 与 `inv_balance` 违反。定位到两个原因，两者都影响规则本身，不只是代码：

### 3.1 故障期**下游**的生产也会失去激活

名义计划可能让恢复期的生产完全依赖故障期的换型，即 $Y=0$、$Z_{\delta}=1$。取消该延续后，恢复期的生产**没有任何激活**，(1.8) 直接把它压到 0。因此修复不能只看"名义上延续被打断的产品"，必须逐个检查**恢复期的每一处生产是否仍然有激活**。

### 3.2 账目容量与实际可行性不等价

- **恢复一次换型要付 $s_i+b_iX$**，不是 $b_iX$。名义上靠延续免掉换型时间的计划，可能在 $b_iX$ 下装得下、在 $s_i+b_iX$ 下装不下。
- 反过来，装得下也可能**没有意义**：有正初始库存时，为已被库存覆盖的需求生产只增加库存成本（机制测试 M6）。

因此修复器改为**评估具体候选计划**（试算 + 内部可行性筛查），而不是相信一个算术界。日志同时记录"账目判断"与"试算结果"，两者不一致时会显式暴露。

另外我最初写的两个**手写名义计划本身不可行**（在"延续免换型"的计划里，恢复期换型 $s+bX$ 超出容量）。按你的要求"修复解必须可行"，机制测试的名义解一律改为**求解所得并经验证的最优解**——这也符合本轮"名义解必须来自优化"的约定。

## 4. 最实质的发现：改善主要来自 $X,I,L$，还是来自释放二元变量？

`J_r - J_LP` 是**不动任何二元变量**就能拿到的改善。逐状态：

| 状态 | $J_r$ | $J_{\mathrm{LP}}$ | $J_r-J_{\mathrm{LP}}$ | κ=1 相对 $J_{\mathrm{LP}}$ | κ=2 相对 $J_{\mathrm{LP}}$ |
|---|---:|---:|---:|---:|---:|
| S0\|D1 | 48 | 28 | **20** | −18 | −18 |
| S0\|D2 | 105 | 105 | **0** | **−58** | **−67** |
| S0\|D3 | 116 | 96 | **20** | −31 | −31 |
| S2\|D2 | 103 | 103 | **0** | **−95** | **−95** |
| S2\|D3 | 67 | 48 | **19** | −2 | −2 |
| S3\|D2 | 62 | 62 | **0** | **−57** | **−57** |
| 其余 6 个 | 5–8 | 5–8 | 0 | 0 | 0 |

两点值得记录，因为它们直接决定下一轮该测什么：

1. **有些状态的改善全部来自 $X,I,L$**（$J_r-J_{\mathrm{LP}}=20$ 或 19）。这部分**在任何后续统计中都不能算作"选择变量组"的贡献**。若不做这一步测量，很容易把 $X,I,L$ 的收益误记成学习器的功劳。
2. **另一些状态 $J_r-J_{\mathrm{LP}}=0$，修复完全无用，只有释放二元变量才有收益**（S0\|D2：$105\to47\to38$；S2\|D2：$103\to8$；S3\|D2：$62\to5$）。这三个状态集中在"机器1停机2期"——修复器无法在恢复期重建全部二元结构。

同时，$\kappa$ 的价值差异很大：S2\|D2 与 S3\|D2 只需 $\kappa=1$（改一个换型）就基本回到名义成本，而 S0\|D2 需要 $\kappa=2$ 仍有 38。**这正是"联合调整"假设可能起作用的区域，但本轮实例只有 2 产品 × 2 机器 × 3 时段，不足以判断。**

六个状态上修复成本等于名义成本、释放也毫无改善（S1 三个、S2\|D1、S3\|D1、S3\|D3）。原因是故障机器在这些计划里本就没有承担关键生产。**这是实例的性质，不是流程错误**；本轮实例承担正确性验证，不据此判断研究方向。

## 5. R1 释放集合的固定索引规则（落盘可查）

$R_1$ 取**字典序第一个**位于非停机位置的短期变量，不依赖任何解的质量（实际落盘值）：

| 故障 | $R_1$ | 说明 |
|---|---|---|
| D1 机器0停机1期 | `(0,0,2)` | $t=1$ 时机器0停机，故跳到 $t=2$ 的机器0 |
| D2 机器1停机2期 | `(0,0,1)` | 机器0未停机，取第一个 |
| D3 双机停机1期 | `(0,0,2)` | $t=1$ 两台机器都停机 |

实测（同 $\kappa$ 下 $R_0$、$R_1$、$R_{\text{all}}$ 的最优成本）：

| 状态 | $\kappa=1$：$R_0$ / $R_1$ / $R_{\text{all}}$ | $\kappa=2$：$R_0$ / $R_1$ / $R_{\text{all}}$ |
|---|---|---|
| S0\|D1 | 28 / 28 / **10** | 28 / 28 / **10** |
| S0\|D2 | 105 / 105 / **47** | 105 / 105 / **38** |
| S0\|D3 | 93 / **65** / **65** | 93 / **65** / **65** |
| S2\|D2 | 66 / 66 / **8** | 66 / 66 / **8** |
| S3\|D2 | 62 / 62 / **5** | 62 / 62 / **5** |
| 其余 7 个 | 三值相同 | 三值相同 |

结论有两点，都与"择优选择变量组"无关但必须记下：

1. **$R_1$ 只在 S0\|D3 一个状态上带来了改善**；其余 11 个状态 $R_1$ 与 $R_0$ 同值。$R_1$ 是固定索引而非择优选择，所以这不构成"选择很重要"的证据。
2. **在 S0\|D2、S2\|D2、S3\|D2 上 $R_1$ 完全无效，而释放全部短期变量收益巨大**（105→47、66→8、62→5）。

> **更正（Stage 03 已证实，2026-09-26）**：本报告初稿由此推出"必须改动的是一个组合，而不是单个换型"，**这个推论是错的**。Stage 03 的完整收益表显示，$R_1$ 无效只是**固定索引选错了变量**：这三（实为两）个状态都存在有效的**单变量**释放（S2\|D2 与 S3\|D2 的最优单变量即为 $R_1$ 之外的那个变量；S0\|D2 的最优单变量为 `(1,0,2)`）。三个状态中**只有 S0\|D2 真正需要两个变量**（105→47→38）。严格结论应为：**固定索引选到的那个变量无效，但存在有效的单变量释放。** 详见 `../stage03_neighborhood_landscape/stage03_report.md`。

## 6. 发现并修正的一个自身错误（稳定性约束）

第一版稳定性约束写成两行绝对值线性化，其中第二行右端项符号错误，退化为 $-\sum_{\text{all}}Y\le\kappa-NM\tau$——**这是被任何 $Y^r=1$ 的计划违反的伪约束**，导致 12/12 状态的 $\kappa=0$ 直接不可行。

正确形式（$Y$ 与 $Y^r$ 均为二元时精确）：

$$\sum_{i,j,t\le\tau}\big|Y_{ijt}-Y^r_{ijt}\big|\le\kappa
\iff \sum_{Y^r=0}Y_{ijt}+\sum_{Y^r=1}\big(1-Y_{ijt}\big)\le\kappa$$

即

$$\sum_{Y^r=0}Y_{ijt}-\sum_{Y^r=1}Y_{ijt}\ \le\ \kappa-|\{Y^r=1\}|$$

**只需一行**，不需要镜像行。$X,I,L,Z$ 不受该约束影响。修正后 12/12 状态通过。该错误的代码注释已保留，说明为什么不能"镜像"。

## 8. 下一轮的判据建议

本轮已把环境打通。初稿据第 4、5 节提出：

> 在 $J_r-J_{\mathrm{LP}}=0$、而释放二元变量才有收益的三个状态（S0\|D2、S2\|D2、S3\|D2）上，**释放一个变量完全无效**（$R_1$ 与 $R_0$ 同值），**释放全部则收益巨大**（105→47、66→8、62→5）。

> **更正（Stage 03 已证实）**：由此推出的"必须改动的是一个组合，而不是单个换型"**是错的**。$R_1$ 无效只是**固定索引恰好选到了无效的那个变量**。Stage 03 的完整收益表（37 个子问题/状态）显示：S2\|D2 与 S3\|D2 的最优单变量就在 $R_1$ 之外，单变量即可达到最优；**只有 S0\|D2 真正需要两个变量**（105→47→38）。严格结论是"固定索引选到的那个变量无效，但存在有效的单变量释放"。另，"修复完全无效"应改为"固定二元变量后的连续优化没有额外收益"——修复器已经完成了恢复可行性的任务。详见 `../stage03_neighborhood_landscape/stage03_report.md`。

因此下一轮的判据不再是"释放全部比固定索引好"，而应由 Stage 03 的收益表决定：**两步贪心在这十二个状态上全部达到最优，贪心遗憾恒为 0**。据此，后续重点应转向**较大规模下的搜索成本**，而不是继续在小实例上寻找需要联合选择的证据。
