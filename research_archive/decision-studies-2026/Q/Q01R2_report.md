## 1. 读取点分类修正

**判据：** 在 `cap` 处超时，环境合法揭示的是「`x ≥ cap`」。
要用它淘汰「`x ≥ b`」的候选，必须**揭示的下界本身已经蕴含** `x ≥ b`。

| 实际截止值 | 超时后是否知道 `x ≥ b` | 据此淘汰是否合法 |
|---|---|---|
| `cap < b` | 不知道 | **不合法** |
| `cap = b` | 知道 | **合法** |

### 1.1 逐个位置

| 位置 | 实际截止值 | 揭示 | 蕴含 `x ≥ b` | 判定 |
|---|---|---|---|---|
| `limeqo.py:89` | timeout_tolerance = min(alpha*best, beta*pred) | x >= cap | only if cap >= b | **违规**（cap<b 时） |
| `limeqo_plus.py:114` | same as above | x >= cap | only if cap >= b | **违规**（cap<b 时） |
| `limeqo.py:114` | current best b (random fallback) | x >= b | yes | **合法** |
| `limeqo_plus.py:139` | current best b (random fallback) | x >= b | yes | **合法** |
| `greedy.py:74` | current best b | x >= b | yes | **合法** |
| `random.py:60` | current best b | x >= b | yes | **合法** |
| `qo_advisor.py:68` | current best b | x >= b | yes | **合法** |

**移出违规清单（我上一轮判错）：**

- `limeqo.py:114` —— 截止值**就是**当前最好值 b，超时本身即揭示 `x ≥ b`
- `limeqo_plus.py:139` —— 截止值**就是**当前最好值 b，超时本身即揭示 `x ≥ b`
- `greedy.py:74` —— 截止值**就是**当前最好值 b，超时本身即揭示 `x ≥ b`
- `random.py:60` —— 截止值**就是**当前最好值 b，超时本身即揭示 `x ≥ b`
- `qo_advisor.py:68` —— 截止值**就是**当前最好值 b，超时本身即揭示 `x ≥ b`

这五处是随机补足/贪心/随机策略路径，它们**读取真值来产生反馈是合法的环境模拟**。

**确认违规（收窄后）：**

- `limeqo.py:89`、`limeqo_plus.py:114` —— **预测驱动路径**的容忍度 `min(α·b, β·pred)`
  可能**低于**当前最好值 b；此时用隐藏真值淘汰候选，超出了该次执行揭示的信息。
- `limeqo.py:35`、`limeqo.py:105` —— **特权停止规则**，另列（见 §2）。

**因此问题应限定为：**

> **LimeQO / LimeQO+ 的预测驱动路径在 `cap < b` 时，额外利用隐藏真值决定候选资格。**

**不得再按表达式形状扩张违规清单。**

## 2. 特权停止规则（仍单列）

本轮不再只是「声明它会失败」，而是给出**一个它确实会给出不同判断的真实对照对**：

规则：`while min_observed.sum() > opt_time + 20`（`limeqo.py:35`）。
`min_observed` 由**掩码后**的矩阵计算，因此两个世界相同；
`opt_time` 是**完整隐藏矩阵**的逐行最小值，因此可以不同。

| 世界 | `min_observed.sum()` | `opt_time` | 继续探索？ |
|---|---:|---:|:--:|
| W_same_hidden_optimum | 200 | 100 | **True** |
| W_different_hidden_optimum | 200 | 260 | **False** |

两行合法反馈完全相同，停止判断却相反 —— 这就是特权停止条件被暴露的方式。

## 3. 状态快照修正

旧实现只保存字典的**键**：

```python
"mask": sorted(self.mask),      # 只有键
"bounds": sorted(self.bounds),  # 只有键
```

这正是你举的反例：一个策略保存完成值 5、下界 2，另一个保存完成值 9、下界 8，
旧快照仍判定相等。修正后：

```python
"mask": sorted((list(k), v) for k, v in self.mask.items()),
"bounds": sorted((list(k), v) for k, v in self.bounds.items()),
```

并且**验收快照中的成本不再四舍五入**（`spent` 保持原值）。

实测：

- 键快照相等：**True**（旧缺陷）
- 值快照相等：**False**
- 修正后的快照能抓住键快照漏掉的差异：**True**

## 4. 检查 4 接入真实环境

旧版本只比较了两份手写常量。现在两份**完整小矩阵**经过**同一个 runner**：

```
runner(truth, best, plan):  env = ReplayEnvironment(...); pol = LegalPolicy()
                            for (q,h,cap) in plan: observe -> record
```

两份矩阵只差一个未揭示的单元格 `(0,2)`：世界 A 为 7.0，世界 B 为 900.0。

| 量 | 结果 |
|---|---|
| 揭示的反馈逐条相同 | **True**（两条都是 `(0,0)@cap10` 超时、`(0,1)@cap2` 超时）|
| 下一动作 | A=[0, 1]，B=[0, 1] → **相同** |
| 固定预算停止判断 | A=True，B=True → **相同** |
| 策略状态 | 相同 = **True** |

这才证明了原要求：**从两份隐藏数据经过实际回放入口运行，策略动作与预算停止判断保持不变。**

原先那两份手写常量只证明了「给简单策略相同的手写输入会得到相同动作」——这是不够的。

## 5. 下界取最大值与合法剪枝

旧实现每次超时直接覆盖：`self.bounds[(q,h)] = val`，
所以「先截止 10 秒、再截止 2 秒」会把下界从 10 降成 2。修正为：

$$L_{qh} \leftarrow \max(L_{qh},\ cap)$$

实测：

- 先 `cap=10`（收费 10）再 `cap=2`（收费 2），存储下界保持 **10**
- 下界保持最大值：**True**

**并且补充了一条我上一轮漏掉的合法剪枝。**
「超时不能判断是否超过当前最好值」**只适用于 `cap < b`**：
若已有下界 `L_{qh} ≥ b_q`，该候选**已不能直接改善当前最好值**，可以合法剪枝。

| 情形 | 剪枝 |
|---|---|
| `(0,0)` 揭示 b=10；`(0,1)` 下界 L=10 ≥ b=10 | **合法剪枝** = True |
| `(0,1)` 仅在 `cap=2` 超时，L=2 < b=10 | **拒绝剪枝** = True |

**这一条对后续基线很重要：** 后续基线必须利用这个合法剪枝。
否则我们可能人为制造大量无效重试，再把「避免它们」包装成学习优势。

若将来要研究「执行更差计划以获取跨查询信息」，那应作为**另一种明确动作与目标**，
不能混在这里。
